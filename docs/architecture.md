# Архитектура прототипа mail-gateway

Прототип построен вокруг `AdaptivePolicyOrchestrator` — компонента, который принимает разобранное письмо и формирует цепочку проверок. Такой подход отражает идею адаптивного механизма фильтрации: разные письма могут получать разную глубину анализа в зависимости от политики, признаков риска и контекста.

## Конвейер обработки

1. `parser.py` разбирает EML-файл, извлекает заголовки, текст, HTML, ссылки и вложения.
2. `checks/session.py` выполняет первичную проверку сессии и метаданных отправителя.
3. `checks/auth.py` анализирует результаты SPF/DKIM/DMARC по заголовкам письма.
4. `checks/content.py` ищет ключевые слова и DLP-паттерны.
5. `checks/urls.py` проверяет URL на фишинговые признаки.
6. `checks/attachments.py` анализирует вложения, расширения, хеши и ZIP-архивы.
7. `checks/ml.py` применяет обучаемый наивный байесовский классификатор.
8. `orchestrator.py` суммирует риск и принимает решение: deliver, quarantine, reject.
9. `syslog_cef.py` формирует событие безопасности для SIEM.

## Соответствие микросервисной архитектуре из ВКР

В учебном репозитории компоненты представлены как Python-модули, чтобы проект можно было запустить локально без сложной инфраструктуры. При промышленном развитии каждый модуль может быть выделен в отдельный сервис: SMTP Gateway, URL Analyzer, Attachment Analyzer, ML Service, Quarantine Service, Management API.
